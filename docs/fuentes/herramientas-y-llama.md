### Perplexity: búsqueda web y reproducibilidad

- La búsqueda web es opcional en la Agent API: "Web search is opt-in". Una petición con solo `model` e `input` responde con el conocimiento del modelo y sin citas; se activa con `tools: [{"type": "web_search"}]` o con un nivel `effort`. Fuente: https://docs.perplexity.ai/docs/agent-api/quickstart.md (2026-11-14).
- Cada nivel `effort` agrupa modelo, configuración de búsqueda, pasos de razonamiento y herramientas, y todos los niveles con herramientas documentadas incluyen `web_search`. Por tanto, no enviar `effort` ni `web_search`. Fuente: https://docs.perplexity.ai/docs/agent-api/effort.md (2026-11-14).
- La página no afirma qué ocurre si se omiten `effort` y `tools` a la vez en todos los modelos; la página de inicio lo indica solo para `model`+`input`. Comprobación empírica recomendada: comprobar que la respuesta no trae citas. Si Sonar (`perplexity/sonar`, "grounded search model") busca siempre: PENDIENTE DE CONFIRMAR (la página de modelos no lo detalla).
- Conclusión: es desactivable en la Agent API (opt-in); la pregunta de si Sonar busca siempre queda abierta, por lo que conviene no usar `perplexity/sonar` en el experimento.

### Recomendación

OpenRouter con `meta-llama/llama-4-maverick`: es el único candidato verificado con Llama grande disponible por API compatible con OpenAI (mismo código de cliente que OpenAI), herramientas aceptadas y una asignación gratuita inicial; Amazon Bedrock (`meta.llama4-maverick-17b-instruct-v1:0`) queda como alternativa de proveedor único pero sin formato OpenAI, con ciclo de vida "Legacy" y fin de vida el 2027-03-30.

Antes de fijarlo: hacer una llamada de prueba con las dos herramientas, anotar qué proveedor sirvió la petición y registrar la fecha, porque el enrutador puede cambiar de proveedor.

## 4. Decisión propuesta de protocolo del agente por proveedor

| Proveedor | Protocolo | Detalles de implementación apoyados en las fuentes |
|---|---|---|
| Anthropic | Llamadas a herramientas nativas (`tool_use` / `tool_result`) | `tool_choice: {"type": "auto"}` únicamente (los modelos 5.5 rechazan `any` y `tool`); `strict: true` en ambas herramientas; reenviar sin modificar los bloques `thinking`; si se quiere una llamada por turno, `disable_parallel_tool_use: true`. |
| OpenAI | Llamadas a funciones nativas por Responses API | `strict: true` con `additionalProperties: false` y todas las propiedades en `required`; solo dos funciones, muy por debajo del límite blando de 20. |
| Perplexity | Funciones nativas por Agent API (`function_call` / `function_call_output`), sin declarar `web_search` y sin `effort` | Solo si se confirma que el modelo elegido admite funciones propias (PENDIENTE DE CONFIRMAR). Si no se confirma, acciones JSON dentro del texto, que además evitan depender de la búsqueda. No usar `perplexity/sonar` salvo que se confirme que no busca siempre. |
| Llama (OpenRouter, `meta-llama/llama-4-maverick`) | Llamadas a herramientas nativas en formato OpenAI (`tools`, `tool_calls`, mensajes `role: "tool"`); enviar `tools` en cada petición | Contingencia: si en la prueba inicial el proveedor devuelve `tool_calls` mal formados, pasar a acciones JSON dentro del texto, con el mismo esquema que las herramientas, validadas en la aplicación. Si se usara Bedrock: Converse sin streaming. |

Protocolo común para el bucle de 6 turnos: el límite de 6 turnos lo impone la aplicación; en el turno 6 se ejecuta con herramientas desactivadas (Anthropic `tool_choice: none`) o se exige una respuesta final, para que el agente cierre siempre con un resultado.
